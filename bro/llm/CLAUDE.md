# bro/llm/CLAUDE.md

Provider-agnostic LLM abstraction and MCP tooling for the `bro` agent system and installed tool providers. `LLM` is the chat interface; an `MCPServer` supplies callable `Tool`s; an `Observer` renders a run live while a `Tracker` records it durably. Run the `llm` CLI (`bro.llm.py`) with `--help` to chat against a provider from the shell.

## Modules

- `bro.llm.py` — the `LLM` ABC (`send(messages)`, holding a `ToolRegistry` + `Observer` + `Tracker` plus an optional `agent` identity) and the `LLMSpec` ABC: a frozen recipe (model + provider knobs) with `create_llm`, `needed_secrets`, an optional `.fast()` / `.with_effort(level)` (a level from `EFFORT_LEVELS`, the neutral low/medium/high/xhigh/max effort vocabulary, mapped per provider), and a `dump` / `from_dict` round-trip keyed by a `TYPE` discriminator so a stored spec rehydrates. `cumulative_usage()` reports the instance's lifetime per-model counts in the four billed token classes (None for providers that don't track). Also the `llm` chat CLI.
- `mu.py` — typed call/content convenience layer over the ChatGPT Responses API. `mu(prompt, result, *contents)` blocks for the roundtrip; `mu.aio(...)` is the awaitable form, which every caller on the agent loop (the script dispatcher, a data source's query summary) uses so the roundtrip neither freezes the session nor outlives an interruption. Both take the provider knobs as keywords: `model` — defaulting to `DEFAULT_MODEL`, the tier that answers a workload the utility was not written for, which a caller whose work is mechanical should pin down to a cheaper one — and `reasoning_effort`. The obligation it puts on a caller is the one its signature does not show: `mu` reads the `openai` key from the credential store itself, so the component calling it must declare that secret (`optional_secrets = ('openai',)`, or `needed_secrets` where the capability cannot degrade without it) for the host to hydrate. Undeclared, the call fails inside a container the key never reached
- `mcp.py` — the tool layer. `Tool` / `MCPServer` ABCs, `FunctionTool` (wraps a Python function, deriving input + output schema via FastMCP's `func_metadata`), and `ToolRegistry` which assembles tools across servers under `namespace__tool` wire names (the canonical form is `namespace::tool`; harnesses resolve `::`→`__`, Claude Code additionally prepends `mcp__`). `validated_callable` / `validate_output` give the HTTP delivery path the in-process fail-fast guard against backend drift; `render_return_shape` renders a tool's output schema into its description (skipped for a shapeless `dict[str, Any]`, whose bare `{}` would only contradict the prose); `render_text` renders `bro.base.template` directives in session-level text (prompts, script bodies) and `select` resolves `bro.base.condition.when`-wrapped entries of a declarative list, both against the surface facts the call site knows — the consuming harness (`#harness` over `Harness`), the wire-name scheme (`#wire` over `Wire`), the environment's credentials (`#creds`); references: `bro/reference/conditions.md` (the model), `bro/reference/template.md` (the directive front). Tool text is different: a server renders its own descriptions and parameter annotations at build time against its own vocabulary — `FunctionTool`'s `variables`, `render_tool_text` / `render_schema_text` — so no unprocessed directive leaves a server and a standalone server serves final text (see `bro/reference/conditions.md` "Server-domain vocabularies"). Servers declare `needed_secrets` / `optional_secrets`, unioned into a bro's hydration set; `MCPServerSpec` is the declaration-side counterpart — pure metadata (secrets + a `build()` factory) that hosts hold and read without constructing a live server, so live servers are free to own real resources. `Toolset[T]` is how a roster-based server module declares itself in one object (namespace + per-server `state` factory + secrets policy), with tools registering on it via the `@spec.tool('description')` decorator (returns the function unchanged, so tools stay directly callable): calling the toolset yields the scoped `MCPServerSpec`, `build()` the live server — rendering each selected tool against the `#tools` roster vocabulary and stamping the definition's full roster on `tool_universe` — and `as_spec` normalizes a declaration entry — a tool-pack module (via its conventional `spec` Toolset), a bare toolset, or a spec — to its full-roster manifest; the static `secrets` class var covers the common case and overriding `get_secrets(tool_names)` covers a credential set that depends on the selected tools. `Context[T]` is the per-call envelope a tool opts into by declaring a `Context`-annotated parameter — excluded from the derived schema and injected on every call carrying the server's long-lived `state`; `MCPServerSpec.of(cls, ...)` stays as the manifest escape hatch for irregular server classes. A sync tool function is called through `bro.base.offload.off_loop` rather than inline, so no toolset can hold the loop for the length of its work; an async one is awaited directly. `MCPServer.close()` is the teardown seam for a live server's real resources — declared per toolset (`Toolset(..., close=...)`, applied to the built `state`) and called once when the bro's lifetime ends.
- `observer.py` — `Observer` ABC streaming run events (reasoning, assistant text, tool call / result) with renderers: `RichConsoleRenderer` (colored panels), `BoringRenderer` (plain text), `NullObserver` (no-op). `rich` is imported lazily so deployed images that never render need not ship it.
- `usage.py` — shared per-model LLM usage accounting, bro-run publishing and Claude transcript discovery, footer formatting/parsing, and the `usage` CLI
- `tracker.py` — the dependency-free `Tracker` ABC, durable sibling of `Observer`, plus the explicit no-op `NullTracker`. Trail records and harness recorders are owned by `bro/trails/`.
- `llms/` — provider specs / implementations, each pairing an `LLMSpec` subclass with its `LLM`:
  - `chat_gpt.py` — `ChatGPT` over the OpenAI Responses API (the real provider; `needed_secrets` → `openai`, `.fast()` → `service_tier='priority'`, `.with_effort()` → `reasoning_effort`, every shared level mapping through). Drives the tool loop over `AsyncOpenAI` and chains each leg on the last response actually received, which is what makes a turn interruptible: cancelling the send parks its unacknowledged input — the request items no response came back for, or the tool outputs plus an `INTERRUPTED_TOOL_OUTPUT` answer for every call the interruption left unanswered (recorded as `tool_result` steps too, so the trail stays replayable) — and the next send leads with them, resuming the conversation the model was stopped in instead of an orphaned branch. Long runs can be bounded by server-side compaction: the spec's opt-in `compact_threshold` (default off) flows to `responses.create` as `context_management`, so the server compacts the chained context in-band once it crosses the threshold. After every `responses.create` it folds the response's `usage` into `cumulative_usage()` (cached input → `cache_read`, the uncached remainder → `input`, `cache_write` 0, reasoning inside `output`) and, when constructed with an `agent`, publishes the snapshot via `bro.llm.usage`'s env-pointed file.
  - `echo.py` — `Echo`, returns the last user message verbatim; the dependency-free default for tests and the `llm` CLI.

## Conventions

- A new provider lives in `llms/`, subclasses `LLMSpec` with a unique `TYPE`, and is added to `_ensure_providers_loaded` / `_spec_for_type` in `bro.llm.py` so `from_dict` and the CLI can find it.
- Importing a provider module must stay cheap: every bro module constructs its `LLMSpec` at class-definition time, so the provider SDK (openai, …) is imported inside the functions that touch the API, never at module level. `chat_gpt.py` is the pattern — annotations resolve through a `TYPE_CHECKING` block, and the SDK enums a spec validates against are mirrored locally with a sync test pinning them to the SDK.
- A `Tool`'s `call` returns `str` for an unstructured tool or a JSON-ready `dict` for a structured one; raising `ToolControlSignal` (vs. a generic exception) escapes the agent loop instead of being fed back to the model as the tool result.
- Acronyms stay all-caps in identifiers (`LLMSpec`, `MCPServer`); `TYPE` discriminator strings are lowercase snake_case (`chat_gpt`, `echo`).
