# bro/llm/AGENTS.md

Provider-agnostic LLM abstraction and MCP tooling for the `bro` agent system and installed tool providers. `LLM` is the chat interface; an `MCPServer` supplies callable `Tool`s; an `Observer` receives typed live events while a `Tracker` records durably. Run the `llm` CLI (`bro.llm.py`) with `--help` to chat against a provider from the shell.

## Design

- **Empty package hub.** `__init__.py` re-exports nothing, and consumers import submodules directly (`from bro.llm.llm import LLM`). `usage.py` reaches no further than `bro.base` and `bro.monitor`, which is what lets an environment without the agent extra read a usage record; a hub re-export would put the provider stack — and the `mcp` dependency behind it — on every import of this package.

## Modules

- `bro.llm.py` — the `LLM` ABC (`send(messages)`, holding a `ToolRegistry` + `Observer` + `Tracker` plus an optional `agent` identity) and the `LLMSpec` ABC: a frozen recipe (model + provider knobs) with `needed_secrets`, an optional `.fast()` / `.with_effort(level)` (a level from `EFFORT_LEVELS`, the neutral low/medium/high/xhigh/max effort vocabulary, mapped per provider), and a `dump` / `from_dict` round-trip keyed by a `TYPE` discriminator so a stored spec rehydrates. `NativeLLMSpec` refines it with `create_llm` — the recipes the bro-native loop can run, and so the type a bro's `llm_spec` takes; a provider whose harness drives its own loop (`claude_code`) is a bare `LLMSpec` and cannot be declared as one. `cumulative_usage()` reports the instance's lifetime per-model counts in the four billed token classes (None for providers that don't track). Also the `llm` chat CLI.
- `providers.py` — the provider roster: `_PROVIDER_MODULES` (name → the module declaring its `LLMSpec` / `DEFAULT_MODEL` / `MODELS` short-name table, imported per name), model resolution (short name, then full id, then verbatim — the table is a convenience, not a whitelist) and `provider_of_model` for the model-without-a-provider case, and the `LLMSelection` a launch's LLM flags parse into: the `provider:model:effort` grammar with its `+fast` suffix, `format()` back to that canonical value, and `resolve(base, selection)` applying it over a standing recipe. `LLMSelectionError` is the one operator-facing failure. The flags themselves are `bro/launch/llm_flags.py`.
- `mu.py` — typed call/content convenience layer over the OpenAI Responses API. `mu(prompt, result, *contents)` blocks for the roundtrip; `mu.aio(...)` is the awaitable form, which every caller on the agent loop (the spell interpreter, a data source's query summary) uses so the roundtrip neither freezes the session nor outlives an interruption. Both take the provider knobs as keywords: `model` — defaulting to `DEFAULT_MODEL`, the tier that answers a workload the utility was not written for, which a caller whose work is mechanical should pin down to a cheaper one — and `reasoning_effort`. A reply the model never finished raises `TruncatedResponse` (it ran out of output tokens, so a smaller input can still succeed) or `IncompleteResponse` (it stopped for any other reason). The obligation it puts on a caller is the one its signature does not show: `mu` reads the `openai` key from the credential store itself, so the component calling it must declare that secret (`optional_secrets = ('openai',)`, or `needed_secrets` where the capability cannot degrade without it) for the host to hydrate. Undeclared, the call fails inside a container the key never reached
- `mcp.py` — the tool layer. `Tool` / `MCPServer` ABCs, `FunctionTool` (wraps a Python function, deriving input + output schema via FastMCP's `func_metadata`), and `ToolRegistry` which assembles tools across servers under `namespace__tool` wire names (the canonical form is `namespace::tool`; harnesses resolve `::`→`__`, Claude Code additionally prepends `mcp__`). `validated_callable` / `validate_output` give the HTTP delivery path the in-process fail-fast guard against backend drift; `render_return_shape` renders a tool's output schema into its description (skipped for a shapeless `dict[str, Any]`, whose bare `{}` would only contradict the prose); `render_text` renders `bro.base.template` directives in session-level text (prompts, spell bodies) and `select` resolves `bro.base.condition.when`-wrapped entries of a declarative list, both against the surface facts the call site knows — the consuming harness (`#harness` over `Harness`), the wire-name scheme (`#wire` over `Wire`), the environment's credentials (`#creds`); references: `bro/reference/conditions.md` (the model), `bro/reference/template.md` (the directive front). Tool text is different: a server renders its own descriptions and parameter annotations at build time against its own vocabulary — `FunctionTool`'s `variables`, `render_tool_text` / `render_schema_text` — so no unprocessed directive leaves a server and a standalone server serves final text (see `bro/reference/conditions.md` "Server-domain vocabularies"). Servers declare `needed_secrets` / `optional_secrets`, unioned into a bro's hydration set; `MCPServerSpec` is the declaration-side counterpart — pure metadata (secrets + a `build()` factory) that hosts hold and read without constructing a live server, so live servers are free to own real resources. `Toolset[T]` is how a roster-based server module declares itself in one object (namespace + per-server `state` factory + secrets policy), conventionally exported as `toolset`, with tools registering through `@toolset.tool('description')` (returns the function unchanged, so tools stay directly callable). `mount(toolset, *tool_names)` validates the selected roster and returns a frozen `ToolLayer` carrying its `MCPServerSpec`; `sh(command, *argument_names)` returns one whose server is generated from an installed CLI command (`cli_tool.py`); `block(*tool_names)` returns the same layer type for harness-native restrictions, and `allow_commands(tool_name, *commands)` the finer statement for a native tool whose argument is a command line — the tool is served, reaching only those commands, a tool narrowed this way is served rather than withheld. The names all three take belong to a consuming harness, so `bro/harness/` owns them and the conditioning that pairs with them. `build()` creates the live server — rendering each selected tool against the `#tools` roster vocabulary and stamping the definition's full roster on `tool_universe`. The static `secrets` class var covers the common case and overriding `get_secrets(tool_names)` covers a credential set that depends on the selected tools. `Context[T]` is the per-call envelope a tool opts into by declaring a `Context`-annotated parameter — excluded from the derived schema and injected on every call carrying the server's long-lived `state`; `MCPServerSpec.of(cls, ...)` stays as the manifest escape hatch for irregular server classes. A sync tool function is called through `bro.base.offload.off_loop` rather than inline, so no toolset can hold the loop for the length of its work; an async one is awaited directly. `MCPServer.close()` is the teardown seam for a live server's real resources — declared per toolset (`Toolset(..., close=...)`, applied to the built `state`) and called once when the bro's lifetime ends.
- `cli_tool.py` — the build side of the `sh(...)` layer: one installed CLI command served as a generated tool in the `sh` namespace, its schema built from the `bro.base.args.CommandSignature` read at build time and its call spelling a fixed argv — long options with their value attached and `--` ahead of the positionals, so a model-supplied value can neither be read as an option nor reach a shell. Output is capped at the shared `DEFAULT_LIMIT` with no parameter of its own, since commands carry their own narrowing flags.
- `observer.py` — the closed provider-neutral `ObservedEvent` union and `Observer.on_event(event)` sink. Providers emit reasoning, interim assistant text, and call-ID-aware tool call/result events (including result error state); `BaseBro` emits turn start plus exact completion, refusal, and failure. The module is display-independent and keeps only `NullObserver` as the explicit no-op.
- `usage.py` — shared per-model LLM usage accounting, bro-run publishing and Claude transcript discovery, footer formatting/parsing, and the `usage` CLI. `from_vendor_counts` is the vendor-raw → four-class normalizer every reader of a recorded usage record goes through. This module speaks of **vendors**, not providers: `vendor_of(slug)` is who billed a resolved model slug and `model_family(slug)` is the key matching two snapshots of one model, both derived from the slug a record carries. The launch-time `provider` of `providers.py` is a different question with a different answer for the same string — a claude slug bills `anthropic` whichever surface ran it, where the roster calls it `claude-code`
- `tracker.py` — the dependency-free `Tracker` ABC, durable sibling of `Observer`, plus the explicit no-op `NullTracker`. Trail records and harness recorders are owned by `bro/trails/`.
- `llms/` — provider specs / implementations, each pairing an `LLMSpec` subclass with its `LLM`:
  - `openai.py` — `OpenAI` over the OpenAI Responses API (the real provider; `needed_secrets` → `openai`, `.fast()` → `service_tier='priority'`, `.with_effort()` → `reasoning_effort`, every shared level mapping through). Drives the tool loop over `AsyncOpenAI` and chains each leg on the last response actually received, which is what makes a turn interruptible: cancelling the send parks its unacknowledged input — the request items no response came back for, or the tool outputs plus an `INTERRUPTED_TOOL_OUTPUT` answer for every call the interruption left unanswered (recorded as `tool_result` steps too, so the trail stays replayable) — and the next send leads with them, resuming the conversation the model was stopped in instead of an orphaned branch. Long runs can be bounded by server-side compaction: the spec's opt-in `compact_threshold` (default off) flows to `responses.create` as `context_management`, so the server compacts the chained context in-band once it crosses the threshold. After every `responses.create` it folds the response's `usage` into `cumulative_usage()` through `usage.from_vendor_counts`, which owns the split, and, when constructed with an `agent`, publishes the snapshot via `bro.llm.usage`'s env-pointed file.
  - `claude_code.py` — the model and knobs a Claude Code session runs under, as a recipe with no client: Claude Code drives its own loop, so the session surfaces read `model` / `effort` / `fast_mode` off the spec (`bro/cw/claude_argv.py` lowers them onto claude's own flags) and the session recorder records its `dump()` as the trail's launch recipe. The field is `fast_mode` rather than `fast` because a same-named field would shadow the `fast()` knob setter it backs.
  - `echo.py` — `Echo`, returns the last user message verbatim; the dependency-free default for tests and the `llm` CLI.

## Conventions

- A new provider lives in `llms/`, exports `LLMSpec` (subclassing `NativeLLMSpec` when the bro-native loop runs it) with `DEFAULT_MODEL` and a `MODELS` short-name table beside it, and takes one row in `providers._PROVIDER_MODULES`. Its `TYPE` is the roster name, so declaring it there is what makes `--provider`, `from_dict`, and the CLI find it. Short names must stay unique across providers — a `--model` with no `--provider` is resolved by whichever roster carries it, and a test holds the rosters disjoint.
- Importing a provider module must stay cheap: every bro module constructs its `LLMSpec` at class-definition time, so the provider SDK (openai, …) is imported inside the functions that touch the API, never at module level. `openai.py` is the pattern — annotations resolve through a `TYPE_CHECKING` block, and the SDK enums a spec validates against are mirrored locally with a sync test pinning them to the SDK.
- A `Tool`'s `call` returns `str` for an unstructured tool or a JSON-ready `dict` for a structured one; raising `ToolControlSignal` (vs. a generic exception) escapes the agent loop instead of being fed back to the model as the tool result.
- Acronyms stay all-caps in identifiers (`LLMSpec`, `MCPServer`). A provider's name is one word wherever it appears — the `TYPE` discriminator, the `--provider` value, its credential kind — lowercase and hyphenated when it needs two (`openai`, `claude-code`, `echo`); only its module file takes the underscore Python requires.
