# workspace/CLAUDE.md

Managed workspaces: the containerization/workspace layer every launch surface builds on. A *workspace* is an isolated per-task copy of the operated repo — a same-machine git worktree or a docker container clone — and this package owns its mechanics: creation and provisioning, the session image, container create/attach/suspend, inspection and teardown, scoped credential-store hydration, the broker spawner adapters, and the session banner. The behavior of the launch stack built on top is `reference/cw.md`; this file owns the code layout.

## Design

- **Harness- and framework-free.** Modules import only `base`, `broker`, and the stdlib — never `bro`, never `cw`. Launch-surface policy — which credentials a launch hydrates, which session state it attaches — stays with the surfaces and reaches a container launch as plain `Launch` data (`extra_mounts` / `env`).
- **Lazy broker import.** `spawn.py` imports broker at module level and is only imported past the `containers.broker_enabled` / `container_broker_enabled` gates — `BROKER_DISABLED` (and an environment whose venv can't import broker) must short-circuit before any broker import, or the kill-switch couldn't save a launch that the import itself crashes.
- **No re-export hub.** Consumers and intra-package code alike import submodules directly (`from workspace.docker import Launch`).

## Components

- `git.py` — `git_out` / `git_run` wrappers, `no_prompt_env`, `rev_parse_commit`, `resolve_ref` (ref → sha with an origin fetch when not local), `resolve_head` (another repo's HEAD → a sha present in this repo's store); both fetches land in nonce-named private `refs/cw/resolve-*` refs so concurrent resolutions cannot read each other's result
- `paths.py` — project-root / workspace-dir / broker control-dir / summon state-dir / host-log dir resolution, `fresh_workspace_name` (mint a `base-<8 hex>` name absent from both workspace namespaces), `venv_env`, `in_container`
- `project.py` — `ProjectConfig` / `project_config()`: the operated repo's `[tool.bro]` launch defaults (required default bro, image repository, and per-kind credential instances), read from the project root's pyproject.toml; `reference/cw.md` "Per-project defaults" owns the behavior
- `docker.py` — broker-free container launch core: `Launch` is the complete supervision-neutral description (workspace, command, scoped secrets, env, mounts, docker knobs); `prepare_container` owns workspace mkdir → image ensure → scoped-store build → `docker create` + store copy. Also thin docker wrappers (`running_mounts`, `find_container_id`, `container_running`), the interactive-attach Ctrl+Z seam (`DETACH_FLAG` + `suspend_until_continued`), image build (`image_tag` content-hashes the setup dirs + project manifests into the project's image repository), create argv, and the forwarded-env set
- `model.py` — the `Workspace` ABC (`HostWorktree` / `ContainerWorkspace`) owning the host/container duality for inspection + teardown (`path`, `ref`, `is_active`, `is_clean`, `remove`, `last_active`, the `from_ref` / `all` factories). The shared clean policy is one `_check_clean(runner, refresh_origin)` parameterized by a `_GitRunner` each subtype supplies (container's alternate-objects dance in `ContainerWorkspace._git_runner`, a no-op on host). Module-level helpers: `format_ref` / `parse_ref` (the `c:` container-ref convention), `host_path_is_clean` (the host policy on an arbitrary path), `_cleanup_image` / `_remove_container_dir` (the force-rmtree-with-root-escalation teardown primitives). Harness session state attached to a workspace is the launch surface's own — its readers and teardown compose around `remove()` at that layer (`cw/claude_config.py`)
- `worktrees.py` — host worktree create (`ensure_host_worktree`) / provision (`provision_host_worktree`, via the shared `setup/provision_repo.sh`)
- `containers.py` — `exec_in_workspace`, `attach_interactive` (the detach → suspend → re-attach loop), and the broker gates: the hold-neutral `broker_enabled` and the container-flavor `container_broker_enabled` (adds the docker-daemon constraint — a macOS daemon runs in a VM and can't bind-mount the host channel socket)
- `spawn.py` — the broker `Spawner` adapters: `DockerLaunchSpec` wraps a neutral `Launch`; `DockerSpawner` adds the provisioned channel mount + `BROKER_CHANNEL`, runs `prepare_container` off-loop, then forks only for stdio/supervision (TTY inherited attach with the Ctrl+Z loop + host-log redirect vs headless merged-output ring + caller-marked workspace teardown); `ProcessSpawner` owns host-process roots; `CompositeSpawner` dispatches on the concrete `LaunchSpec` type so either root mode can spawn docker children; `_HostLogRedirect` moves the host process's output to the per-session host log while an interactive child owns the terminal
- `store.py` — scoped credential-store mechanics: the `ScopedSecrets` tiers, `finalize_scoped_secrets` (strict grant/revoke), `log_scoped_secrets`, `materialize_scoped_store` (a host session's on-disk store, the `CREDENTIALS_REGISTRY` target), and the `docker cp` tarball packing; which names land in the tiers is the launch surface's policy
- `banner.py` — the session banner: `SessionFacts` (typed session facts collected from env + /.dockerenv — `collect`, `render_visual` / `render_llm`, `display_ref`) + `render_banner`, consumed by the `cw banner` CLI, `bro chat`'s opening message, and the `bro::banner` service tool
- `session.py` — in-session control of a managed session: `terminate_session` (SIGTERM to the in-place runner via `CW_RUNNER_PID`, the `raise` service tool's kill path)
