# cw/CLAUDE.md

`cw` launches claude in a managed workspace — either a host **worktree** or an isolated docker **container** clone. The package is the claude-harness launch surface over two lower layers: the `workspace/` package (containerization/workspace mechanics — `workspace/CLAUDE.md`) and `bro/launch/` (the bro-aware host machinery: per-surface credential scopes, summon enforcement, the broker-root composition — `bro/launch/CLAUDE.md`). For *how it actually works* (subcommands, host vs container modes, credential seeding, env vars, `--resume`/`--bro`/`--hold`), read `reference/cw.md` — that document owns the behavior, this one owns the code layout.

## Module map

Leaf utilities (no intra-package deps, or only on each other):

- `constants.py` — `_CW_MODEL` (the claude model every session runs). Its own module so consumers share it without a heavier import
- `flags.py` — `add_forwarded_flags` / `extract_forwarded_argv`: the pass-through flag set `dive-in` forwards into `cw ss`
- `claude_auth.py` — claude-session auth: `_apply_claude_auth` (scrub the outranking `ANTHROPIC_*` vars, overlay the `claude_code` setup-token as `CLAUDE_CODE_OAUTH_TOKEN`) and `_load_anthropic_key` (the apiKeyHelper read behind `--bro` sessions)
- `claude_config.py` — per-session claude state, both modes: the `~/.claude/cw-sessions/<name>` path derivations (`_session_claude_dir`, `_claude_config_dir` / `_claude_projects_dir` / `_encode_claude_path` — a workspace's claude projects dir under the session's config root, one derivation for both modes — and `_latest_jsonl`), the seeded `.claude.json` (`_seed_claude_json`) + constructed session settings, `container_claude_state` (provision the dir and return the `~/.claude` overlay mounts + claude env a claude-running container adds to its `Launch` — a bro-run container mounts none), `_provision_host_claude_dir` (the host session's private state dir: seeded json + settings + first-run plugins copy + legacy transcript migration), and the readers/teardown that compose claude state around a `Workspace` (`workspace_projects_dir`, `read_subject`, `drop_workspace`); `reference/cw.md` "Host claude-state isolation" owns the behavior
- `system_prompt.py` — `_load_base_prompts` / `_session_append_prompt` (the `--append-system-prompt` text: base prompts plus the persona and its canonical script instructions)
- `mcp.py` — session-local HTTP MCP serving through `runtime/mcp_server.py`: `MCPEndpoint` carries the port and token, `_http_mcp_config` builds Claude's namespace map, and `_start_session_mcp_server` / `_SessionMCPServer` own the `mcp-server <spec> --http --port 0` lifecycle (OS-assigned port file, `/health` gate, and termination on session exit)
- `broxy.py` — host-mode session wrapper around `broxy launch`: `_start_session_broxy` chooses a session-tempdir socket + log and `_SessionBroxy` retains the returned address + pid for stop-on-session-exit; returns `None` with a warning when the broxy cannot run, after which the runner unsets `BROKER_CHANNEL`. No broker import, so the module stays importable where broker is not
- `session_context.py` — `build_session_context` / `encode_session_context`: the typed launch-context records (system prompt, git state, MCP servers, root CLAUDE.md) the in-place session runner captures into `CW_SESSION_CONTEXT` for `sync-session-log` → `rewind`
- `session_log.py` — `_start_session_log_sync` / `_SessionLogSync`: the runner-owned `sync-session-log --watch` daemon lifecycle — continuous transcript upload next to claude for every session flavor, stderr to `<claude config dir>/session-log-sync.log`, terminate-on-session-exit as the final sync (`reference/cw.md` "Session-log sync" owns the behavior)

Supporting tools:

- `claude_commit_footer.py` — emits and records per-commit token-accounting deltas, and aggregates them for squash merges; the usage classes and footer format live in `llm/usage.py`
- `print_anthropic_key.sh` — resolves the Anthropic API key for claude's `apiKeyHelper`

Launch + lifecycle:

- `listing.py` — `cw list` (one loop over `Workspace.all(project)`; keeps the `ThreadPoolExecutor` fan-out — mounts fetched concurrently with the per-workspace subject/last_active reads; the subject is the claude-side `claude_config.read_subject`)
- `clean.py` — `cw clean` (one `_assess` over `Workspace.all(project)`; removal goes through `claude_config.drop_workspace` so the claude session state goes with the workspace)
- `claude_argv.py` — `build_claude_launch`, the one claude argv builder for both flavors: the cw-session/bro switch (`--bare` + bro system prompt + `mcp__ns__*` allow-list vs the cw-injected append prompt), the merged `--settings` (fastMode + the workspace's `cw/print_anthropic_key.sh` as apiKeyHelper), and the single handling of `--model` / `--effort` / mcp-config / prompt seeding. Returns `ClaudeLaunch` (argv + the session-shaping prompt text for CW_SESSION_CONTEXT)
- `runner.py` — `run_in_place`, the inner session runner behind the help-suppressed `cw ss --in-place`: assumes cwd is a prepared workspace and owns everything next to claude — the host-mode private claude state dir (via `cw.claude_config`, exporting `CLAUDE_CONFIG_DIR` before anything derives paths; a container's mounts already provide it), cwd-derived `--resume` resolution, the host-mode session broxy (via `cw.broxy`, rewriting `BROKER_CHANNEL` — or unsetting it when the broxy cannot run — before the MCP server and claude inherit it; skipped in a container, where the entrypoint launched the broxy), the session-local MCP server (via `cw.mcp`, /health-gated — `bro:<name>` under `--bro`, `persona:<name>` for a cw-session), CW_SESSION_CONTEXT, the bro git identity (`bro.launch.identity`) + CW_BRO + BRO_HOLD + CW_RUNNER_PID exports (hold and kill wiring for the `raise` service tool's claude mounts — bro/bro.py; the kill itself is `workspace.session.terminate_session`), and the session-log sync daemon (via `cw.session_log`, started after the session context is set and stopped after claude exits)
- `session.py` — the `SessionSpec` dataclass (the parsed session parameters; `to_command_argv` builds `CW_COMMAND` / the resume hint, `resume_variant` clears the create-only inputs, `to_in_place_argv` serializes the inner runner invocation) plus the outer launch layer: `_replace_resume_hint` (the post-exit overwrite of claude's exit hint with `CW_RESUME_COMMAND`, both modes), and `start_session` dispatches to `_container_session` (computes the complete `workspace.docker.Launch`, claude overlay mounts included; the in-place invocation crosses docker as the container command, resolved from the clone's venv) or `_host_session` (the cw-session `claude_code` gate, scoped-store hydration, worktree ensure + provision, the private claude state dir + `CLAUDE_CONFIG_DIR` + `CREDENTIALS_REGISTRY` in the runner env, then the workspace's own `<worktree>/.venv/bin/cw ss --in-place …` — supervised as the broker's root peer behind the `broker_enabled` gate, direct `subprocess.run` when the gate degrades), and the `--into` resolution in `start_session` (without it a new workspace bases on the host checkout's current HEAD — the entrypoint's fallback in container mode, `git worktree add … HEAD` in `ensure_host_worktree` for host mode). Scope computation and the container root run come from `bro/launch` (`scope.preflight_scoped_launch`, `root.run_in_container`)
- `cli.py` — `build_parser` + `main` (policy gates, the `--in-place` dispatch to `runner.run_in_place`; the workspace verbs — list/clean/exec/banner/check-clean — delegate to `cw.listing` / `cw.clean` and the workspace layer); `__cli_name__ = 'cw'` registers the `cw` alias on top of the canonical `cw.cli` script

## Invariants

- **Hub re-export.** `__init__.py` re-exports exactly the cross-package surface `dev/dive_in.py` consumes (`build_parser`, `add_forwarded_flags`, `extract_forwarded_argv`, `fresh_workspace_name`), so that caller keeps `import cw` unchanged. Intra-package code imports `from cw.<module> import …`, never through the hub — a partial-init hazard.
- **Layering.** cw imports `workspace/` (mechanics) and `bro/launch/` (bro-aware launch policy); neither imports cw back. Claude state — paths, seeds, mounts, subject reads, teardown — lives only here (`claude_config.py`) and reaches the lower layers as plain launch data.
- **Lazy bro import.** `bro.registry` is imported function-locally (in `system_prompt`, `bro`) so `import cw` stays cheap — `dev/dive_in.py` imports `cw` at module top level, so a module-level `bro.registry` import would tax every importer. `session.py`'s module-level `bro.launch` imports are the light policy modules (`scope`, `root`), not the registry.
- **Lazy broker import.** The broker package is imported function-locally in `session.py` (and behind `bro/launch/root.py`'s own gate): `BROKER_DISABLED` — and an environment whose venv can't import broker — must short-circuit *before* any broker import, or the kill-switch couldn't save a launch that the import itself crashes.
