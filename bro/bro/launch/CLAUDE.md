# do/CLAUDE.md

Bros launching and managing layer — thin helpers that drive a `Bro` toward a specific outcome. Each file is a single-purpose CLI wrapper; this package is the home for whatever orchestration shows up next.

## Files

- `do.py` (`ask`) — `async do(bro, what)`; forwards to `bro.run(what)` (one-shot). CLI: `ask <bro-name> <what>` (aliased to `ask` rather than `do` since `do` is a shell keyword; `do.do` also works).

  Slash-command expansion: when `what` matches `/<skill-name>[ <args>]`, `do()` looks up the skill via `bro.get_skill_body(name)` and substitutes the skill's markdown body for the user message (body, blank line, `ARGUMENTS: <args>` if args were given) — same shape Claude Code uses for slash commands, so a skill file authored for either surface works on both. Unknown `/<name>` raises `KeyError` (with the bro's available-skill list); `_cli.py` catches it and exits non-zero with the message on stderr.
- `call.py` (`call`) — entry point for an interactive chat with a bro.

  By default opens the Textual chat UI in `call_tui.py` (IM-style: scrollable history, left/right bubbles, timestamp + date separators, animated "Typing…", Ctrl+D to quit, backtick (`) opens a stats modal). Falls back to text mode (`[HH:MM:SS] bro: <reply>` lines + `> ` prompt) when stdin/stdout isn't a TTY; `--text` forces it. The text REPL helper `call_text(bro, initial)` is library-callable.

  The Bro's `interactive=True` machinery picks up automatically in both modes: no `raise` tool, symmetric interactive-mode note injected into the system prompt.

  **Renderers.** Each mode ships its own `Observer` renderer rather than reusing `BoringRenderer` / `RichConsoleRenderer` — those write to stderr which Textual silently swallows during TUI runs, and their multi-line panels don't fit the conversational shape of the text REPL. `TextRenderer` (in `call.py`) renders one-liners matching the `[HH:MM:SS] bro …` aesthetic — `· thinking:`, `· says:`, `→ tool {args}`, `← tool {result}` — with JSON compacted to single lines. `TUIRenderer` (in `call_tui.py`) hops onto the app thread via `call_from_thread` and mounts dim full-width `SystemBubble` rows between user and bro bubbles for each event. Both skip `on_assistant_message` when `terminal=True` — the reply is the value `bro.send` returns and is already rendered by `call_text` (as the `[HH:MM:SS] bro: <reply>` line) or by `ChatApp` (as a bro bubble); emitting again would double-render.

  Flags: `--text` forces text mode (above). `--fast`, `--no-container`, and `--no-trails` are shared with `ask`/`do-task` via `_cli.py` (`maybe_containerize` / `create_bro_for_run`); see "Container isolation". `--fast` builds the bro from `bro.llm_spec.fast()` — provider-specific (for ChatGPT it sets `service_tier='priority'`, the analog of Claude Code's `/fast`: same model/quality, faster, higher per-token price; see `llm/llms/chat_gpt.py`); bros whose spec has no fast equivalent surface a clean error from the base `LLMSpec.fast()`.
- `call_tui.py` — Textual `ChatApp` plus its widgets (`MessageBubble`, `BubbleRow`, `DateSeparator`, `TypingIndicator`, `StatsScreen`). Mounts an `Input` on the bottom and a `VerticalScroll` of bubbles above. `bro.send()` runs in a Textual `@work(exclusive=True)` so the UI stays responsive while the LLM responds
- `do_task.py` (`do-task`) — `async do_task(bro, task)`; shorthand for `ask <bro> /fix <task>`. Wraps any non-slash input as `/fix <task>` and forwards through `do()` so the slash expansion turns it into the `/fix` skill body; if `task` already starts with `/` (e.g. `do-task ppp-dev "/fix --focus"`), it passes through untouched. CLI: `do-task <bro-name> <task>`. Requires the target bro to expose a `/fix` skill (currently only `ppp-dev`).

All modules expose their function for library use (`from do.do import do`, `from do.call import call_text`, `from do.do_task import do_task`) and as a CLI runnable via `python -m do.<module>` or the registered console scripts; CLIs resolve the bro name through `bro.registry.create_bro`.

## Container isolation

`ask` / `do-task` / `call` all re-exec the bro into a throwaway `cw -c`-style container (workspace `var/cw/containers/<cli>-<bro>-<hex>/`, dropped on exit) so the bro's tools operate on `/workspace`, not host paths, and it reads only its scoped credential set. The shared hop is `maybe_containerize` in `_cli.py`; the launch primitive is `cw.run_in_container`, whose `docker start -a -i` gives the container a real `-it` TTY — so interactive `call` renders its Textual UI inside the container just as a claude code session runs in a `cw -c` container.

`CW_IN_CONTAINER=1` (set by the container) short-circuits the re-hop so the inner process runs the bro in-process; `--no-container` opts out for host-side debugging. The scoped set is the bro's `needed_secrets()` plus its LLM key and `trails`, with the docker socket gated on `needs_docker`. `--fast` (available on all three) is forwarded into the container like `--rich` / `--text` and applied to the in-container bro via `bro.llm_spec.fast()`; `call` additionally decides TUI-vs-text on the host and forwards `--text` when the host terminal can't back the TUI (the container's PTY always reports a TTY).

`--grant <secret>` / `--revoke <secret>` (repeatable, on all three) adjust that scoped set before the hop via `credentials.apply_grant_revoke`: final set = `(computed | granted) - revoked`. They are host-side only (not threaded into the inner command), so `maybe_containerize` applies them when it hops and errors when it wouldn't (`--no-container` / already in-container — host runs are unscoped, so a revoke couldn't restrict anything). Strict: granting a secret already in the set, or revoking one absent from it, errors and stops; an unknown grant still fails loudly at hydration. The motivating case is running the emails e2e in a scoped container — `call --fast --grant gmail_creds --grant google_api devoops "…"` keeps devoops scoped to +Gmail instead of forcing whole-host `--no-container`.

`--no-trails` turns recording off: `maybe_containerize` sets `TRAILS_DISABLED` in the container via `cw.run_in_container(extra_env=…)` (the in-container tracker factory then returns `NullTracker`) and drops `trails` from the scoped set. It acts only on the container hop, so it's mutually exclusive with `--no-container`; and unlike `--fast` / `--text` it isn't forwarded into the inner argv — the env var carries the effect in. The recovery use case (deploying `trails-server` through a bro) and the `--no-container` alternative (`TRAILS_DISABLED=1` in the shell) are in `trails/CLAUDE.md`.
